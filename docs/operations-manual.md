# 操作手冊

> 本手冊描述**目前實際交付的軟體行為**。與實作規格書仍有落差之處，見文末
> 「[已知限制與規格差異](#8-已知限制與規格差異)」，操作時務必一併閱讀。

## 1. 啟動程式

- 桌面捷徑或開始功能表的「tfx-quant」。
- 程式會讀取 `%LOCALAPPDATA%\tfx_quant\config\settings.json`；若不存在則使用內建範例設定。
- 設定驗證失敗（時區非 `Asia/Taipei`、平倉時間非 04:55、口數上限 > 2、商品未定義等）會**立即中止**並顯示原因。
- 啟動後開啟「就緒畫面」（ReadinessFrame）。標題列在測試環境會顯示
  「TfxQuant — 測試環境（真實行情・模擬下單）」並有醒目的模擬橫幅。

## 2. 執行環境選擇（模擬下單 ↔ 正式下單）

- 就緒畫面上方的「執行環境」選項：「模擬下單（真實行情）」與「正式下單（PRODUCTION）」。
- 切換到「正式下單」會跳出確認對話框。
- **切換時機限制**：只有在策略非執行中、且沒有任何活動委託時才能切換；否則會提示
  「策略目前為 …，請先停止策略再切換執行環境」或「尚有活動委託…」。
- 切換會整個重建執行環境（重新登入）。

## 3. 登入

### 3.1 正式環境（PRODUCTION）

- 按右上角「登入」開啟登入對話框，輸入：
  - 元大期貨帳號（`F` 開頭）
  - 密碼
  - （首次或換憑證時）憑證檔路徑與憑證密碼，按「匯入憑證」
  - 可勾選「安全儲存密碼」，僅登入成功後才會寫入 Windows 認證管理員
- 登入同時建立**交易連線**與**行情連線**（行情為獨立驗證，不由交易登入推導）。
- 右上角狀態文字會顯示交易 / 行情登入狀態；「登入」按鈕在已連線時變為「登出」。

### 3.2 測試環境（TEST）

- 交易端為本機模擬器，**不需要也不接受**交易帳密（模擬器只認保留帳號 `TEST-SIMULATION`）。
- 按「行情登入」只輸入**行情**帳號與密碼，登入真實行情。

## 4. 選擇商品與契約

- 「市場行情」區的「切換行情」可在小台指（MXF）與大台指（TXF）之間切換**監看**對象。
- 契約年月為 `AUTO`：自動解析近月並顯示「契約年月：YYYYMM（自動近月）」。
- **交易商品固定為小台指（MXF）**。切換監看不會改變下單商品；策略只會對 MXF 產生交易意圖。

## 5. 策略運作

- 目前版本**沒有**「啟動 / 暫停 / 停止策略」按鈕。程式開啟、行情可用且商品已解析後，
  60 分鐘策略引擎即持續運作，收到每根收盤 60 分 K 後評估並在符合條件時經 `OrderManager`
  送出委託（測試環境送到本機模擬器）。規則見[策略規格](strategy-spec.md)。
- 新進場／加碼會在下列情況**自動被擋下**（風控平倉不受影響）：
  - 行情資料 stale 或有缺口（`data_reliable = false`）
  - 該契約已有活動委託
  - 自動持倉核對偵測到本機與線上不一致（`position_state_uncertain`）——會在下次自動核對
    重新確認一致後自動解除
  - 時間位於 04:55–10:45 禁入時段
  - 20MA 樣本不足、均線走平、K 棒方向不符

## 6. 畫面欄位

| 區塊 | 內容 |
|---|---|
| 上方狀態列 | 品牌名、執行環境選項、交易/行情登入狀態、「查看所有日誌」、「登入／登出」 |
| 市場行情（切換行情） | 監看商品、`契約年月：YYYYMM（自動近月）` |
| 市場行情圖 | 60 分 K 線圖（即時監看／歷史查詢切換、滾輪平移、Ctrl+滾輪縮放）、資料來源與最後更新狀態；行情 stale／斷線／缺口／不完整 bar 會顯示於狀態列 |
| 交易活動 | 目前持倉、活動委託、已實現／未實現／總 P&L、持倉成本、成交價、數量、方向、手續費、交易稅、滑價、委託／成交時間、交易原因摘要（測試環境所有列標示 `simulation`） |
| 自動持倉核對 | 「等待登入後自動核對本機與線上持倉」／最新核對結果與差異說明 |
| 緊急平倉 | 「緊急平倉（重新查詢）」→ 顯示查得的線上淨部位 → 「確認緊急平倉」 |

## 7. 報表

- 交易報告可依**交易日、商品、方向、workflow / correlation ID** 查詢。
- 明細可從策略 decision 追溯到 intent → 模擬／真實委託 → ack → 成交 → 持倉變化 → P&L
  （時間軸來自 audit 資料庫 `%LOCALAPPDATA%\tfx_quant\logs\audit.sqlite3`）。
- 測試環境與正式環境共用相同 report schema、查詢與匯出格式；測試環境每筆成交與報表
  不可移除地標示 `simulation=true`。
- 未實現損益需要有效的即時報價才會計算；行情 stale／斷線／gap 時顯示為未知並標示最後
  更新時間，不以合成價格補值。

## 8. 一般文字日誌視窗

- 上方「查看所有日誌」開啟日誌視窗，顯示程序記憶體中最近的結構化事件（人類可讀格式）。
- 完整永久 log 位於 `%LOCALAPPDATA%\tfx_quant\logs\`，見[除錯日誌](debug-logging.md)。

## 9. 正常關閉

- 直接關閉視窗即可。程式會依序停止：策略訊號服務 → 風控 → 連線監控 → 持倉核對 →
  OrderManager → 行情 runtime → 事件協調器（等待處理佇列清空，逾時 5 秒）。
- **不留倉前提**：系統設計為每日 04:55（Asia/Taipei）前完成收盤平倉。若當日仍有部位，
  請確認 04:55 收盤平倉已完成，或於收盤前使用「緊急平倉」，必要時向券商確認。

## 10. 已知限制與規格差異

實作規格書假設的下列機制，**目前版本尚未提供**，操作時請特別注意：

1. **無策略啟動／暫停／停止 UI**，也無 `StartupSafetyGate` 九項啟動檢查作為硬性
   進入條件。程式開啟且行情可用時策略即在運作。若要停止交易：登出、或關閉程式。
2. **無正式的「安全暫停 → 人工確認 → 恢復」狀態流程。** 連線中斷、持倉核對差異、
   查詢失敗會被偵測並寫入 log，並（對持倉差異）自動擋下新進場／加碼，但不會有一個
   需要操作人員按「恢復」的暫停狀態。處置方式見[安全 runbook](safety-runbook.md)。
3. UI 不提供人工重新查詢或人工同步持倉的按鈕（此為刻意設計）。持倉一致性由自動核對維護。
4. 正式環境真實成交的手續費／交易稅在成交回報是否帶入尚待元大文件確認；確認前一律
   標示 `provisional`。
