# Feature 05 — 60-Minute Strategy Signal Engine

> **API 文件唯一來源：實作前必須直接讀取專案根目錄 [`交易API元件及說明文件/`](../../交易API元件及說明文件/) 內的元大期貨交易 API 說明、Python 範例、元件與版本資訊。禁止使用 SPARK API 網站、舊 SPARK SDK、舊範例或既有 SPARK 程式碼反推 API；若與本 prompt 其他描述衝突，以該資料夾內文件為準。資料夾缺少、文件未明載或內容矛盾時，須停止相關實作並列為 blocker。市場價格、行情與 OHLCV 不屬於此交易 API 規格，一律使用 `yfinance`。**
> **不得臆測：API 名稱、參數、回傳值、事件、錯誤碼、登入方式、環境、平台、位元數與能力都必須有上述官方文件依據；文件未明載者須標成待確認並隔離於 adapter，不得自行補造。**

> 強制使用 Python 開發；策略須為不依賴 UI 或券商 SDK 的純 Python 領域模組。

## 任務

以純領域邏輯實作 60 分 K 訊號，不直接呼叫元大 API。輸入只能是已收盤 K 棒、策略狀態、經核對的實際持倉與交易時段，輸出為意圖（建倉、加碼、平倉／反手請求或不動作），由下單協調器決定是否可送單。

## 規則

- 連續兩根紅 K 且目前空手時，產生建立 1 口多單意圖。
- 已持有 1 口多單後，再出現「符合條件」的紅 K 時加碼至 2 口；最大多單 2 口。
- 連續兩根黑 K 時請求平掉全部多單，之後才可由反手模組建立 1 口空單。
- 空單完全鏡像：連續兩根黑 K 空手建 1 口空單；持有 1 口後符合黑 K 條件加至 2 口；連續兩根紅 K 平空並請求反手多 1 口。
- 十字 K 中斷連續方向；同一根已收 K 只能評估一次，重送事件不得重複產生意圖。
- 08:45 與 09:45 不建倉，日盤最早在 10:45 的判斷點建倉；暫停、停止、行情不新鮮、未同步或接近 04:55 時不得建立／加碼。

## 必須消除的歧義

在正式程式啟用前，將「持有 1 口後，再出現符合條件的紅／黑 K」做成明確可設定且有測試的定義，例如：(A) 每一根同色收盤 K 即可加碼；或 (B) 再完成一組連續兩根同色 K 才加碼。預設採較保守的 B，但 UI 與文件必須顯示目前設定，並取得客戶確認。

## 除錯日誌需求

- 每次已收 K 評估都記錄 bar ID、OHLC、紅／黑／十字分類、連續計數前後值、策略狀態、實際持倉、允許時段及設定版本。
- 無論產生或不產生訊號，都須記錄每條規則的布林結果、最終 decision、signal ID 與明確阻擋原因；重複 bar 或過期 bar 須記錄去重／忽略依據。
- 訊號狀態重置、每日切換、加碼資格及 reversal 意圖須以 correlation ID 串接後續 risk／order workflow，且不得把行情內容誤記成已送單或已成交。

## 狀態與驗收

保存最後處理 bar ID、連續色彩計數、上次訊號與待處理意圖。停止、人工同步、商品切換或交易日重置時清除狀態；一般暫停不得擅自補送暫停期間訊號。用表格驅動測試覆蓋空手、±1、±2、十字 K、重複 bar、禁止時段、暫停與每日重置，並證明不會產生超過 2 口的目標。
