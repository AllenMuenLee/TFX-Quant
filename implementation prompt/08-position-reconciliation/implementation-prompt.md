# Feature 08 — Position Reconciliation and Manual Sync

> **平台硬性限制：整個系統只能使用 x32；不得使用 x86 或 x64。原因是行情 API 僅提供 x32 版本。所有開發、相依套件、執行環境、測試、建置與部署均須遵守此限制。**

> 強制使用 Python 開發；部位核對與人工同步須實作成獨立 Python service。

## 任務

持續比較元大實際持倉、系統依已知成交推導的 expected position 與策略認知持倉。元大查詢結果是人工確認同步時的新基準，但任何差異在自動採納前都必須安全暫停。

## 必須實作

- 在登入、啟動策略、每次成交、反手全平閘門、重連、定時輪詢及回到前景時查詢持倉與活動委託。
- 僅比較目前交易帳號與完整契約；同時顯示其他契約持倉供警示，避免漏掉風險。
- 若實際持倉與 expected position 在方向或口數上不同，立即進入 `PausedSafe`，阻止所有自動新單，記錄差異快照與可能原因（手機 App／人工／其他程式）。
- 提供「重新查詢」及「確認以元大實際持倉同步」兩步人工流程；按鈕需顯示帳號、商品、契約、實際口數與時間，並要求明確確認。
- 同步前必須確認無活動或未知委託；有未知委託時禁止同步，先由人工在券商端釐清。
- 同步成功後更新 expected baseline，清除待執行策略 intent，重置連續 K、最後訊號及加碼／反手 workflow；保持暫停，必須再次人工啟動。
- 不得把持倉差異自動解釋成策略成交，也不得自動下單「修正」差異。

## 驗收

模擬手機 App 建倉、平倉、部分平倉、反向持倉、不同契約交易及查詢暫時失敗。驗證差異能在下一次回報或輪詢時停機、同步有完整 audit record、狀態確實重置，且同步本身不送任何單。
