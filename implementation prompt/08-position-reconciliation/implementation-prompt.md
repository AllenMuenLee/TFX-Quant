# Feature 08 — Automatic Position Reconciliation

> **API 文件唯一來源：實作前必須直接讀取專案根目錄 [`交易API元件及說明文件/`](../../交易API元件及說明文件/) 內的元大期貨交易 API 說明、Python 範例、元件與版本資訊。禁止使用 SPARK API 網站、舊 SPARK SDK、舊範例或既有 SPARK 程式碼反推 API；若與本 prompt 其他描述衝突，以該資料夾內文件為準。資料夾缺少、文件未明載或內容矛盾時，須停止相關實作並列為 blocker。市場價格、行情與 OHLCV 不屬於此交易 API 規格，一律使用 `yfinance`。**
> **不得臆測：API 名稱、參數、回傳值、事件、錯誤碼、登入方式、環境、平台、位元數與能力都必須有上述官方文件依據；文件未明載者須標成待確認並隔離於 adapter，不得自行補造。**

> 強制使用 Python 開發；自動部位核對須實作成獨立 Python service。

## 任務

持續自動比較元大線上實際持倉、電腦依已知成交保存的 expected position 與策略認知持倉。任何查詢失敗、方向／口數差異或其他契約非平倉部位都必須立即安全暫停，不得提供使用者手動重新查詢或手動採納線上部位的按鈕。

## 必須實作

- 在登入、啟動策略、每次成交、反手全平閘門、重連、定時輪詢及回到前景時查詢持倉與活動委託。
- 比較目前交易帳號與完整 MXF 交易契約；同時自動檢查其他契約持倉，任何其他契約非平倉部位視為異常並安全暫停。
- 若實際持倉與 expected position 在方向或口數上不同，立即進入 `PausedSafe`，阻止所有自動新單，記錄差異快照與可能原因（手機 App／人工／其他程式）。
- UI 為唯讀狀態顯示，只呈現遮罩帳號、交易商品、契約年月、本機紀錄、線上紀錄、線上時間與一致／異常結果；不得提供重新查詢或確認同步按鈕。
- 不得自動以線上結果覆寫 expected baseline。異常後維持安全暫停，由後續受控復原流程處理；有活動或未知委託時同樣不得自動採納。
- 不得把持倉差異自動解釋成策略成交，也不得自動下單「修正」差異。

## 除錯日誌需求

- 每次 position query 記錄 query ID、觸發來源、帳號遮罩、商品契約、broker snapshot 時間、回傳筆數、彙總淨口數、耗時與錯誤碼。
- reconciliation 須記錄本地預期、券商實際、活動／未知委託、差異分類、採取動作及 readiness 結果；差異不得只以自由文字呈現。
- 自動核對須記錄觸發來源、同步前後快照、異常分類、查詢失敗及是否進入 `PausedSafe`，並以 audit/correlation ID 串起全流程。

## 驗收

模擬手機 App 建倉、平倉、部分平倉、反向持倉、不同契約交易及查詢暫時失敗。驗證差異或查詢失敗能在下一次自動觸發時停機、UI 無人工重查／同步按鈕、核對有完整 audit record，且核對本身不送任何單。
