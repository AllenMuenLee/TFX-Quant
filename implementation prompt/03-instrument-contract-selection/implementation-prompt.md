# Feature 03 — Instrument and Contract Selection

> **平台硬性限制：整個系統只能使用 x32；不得使用 x86 或 x64。原因是行情 API 僅提供 x32 版本。所有開發、相依套件、執行環境、測試、建置與部署均須遵守此限制。**

> 強制使用 Python 開發；商品主檔、驗證與切換流程須實作成可測試的 Python services。

## 任務

實作小台指與大台指商品切換、契約月份解析與有效性驗證。商品代碼、契約格式、到期日與可交易月份必須取自元大 API 或受控商品主檔，不得把可能變動的代碼規則散落在程式中。

## 必須實作

- 建立商品主檔服務，能表示小台／大台、契約代碼、月份、到期日、tick size、乘數、交易時段與是否可交易。
- UI 可選小台或大台及明確契約月份；若支援近月自動選擇，必須顯示解析後契約並要求啟動前確認。
- 策略執行中或存在持倉、活動委託、未知委託時禁止切換商品／契約。
- 切換流程必須先暫停，取消舊行情訂閱，重新查詢帳戶狀態，訂閱新契約並清空 K 棒／訊號狀態；成功後仍需使用者重新啟動。
- 到期、停止交易、主檔缺漏、價格跳動單位不符時禁止建倉並顯示原因。
- 所有委託都攜帶商品與完整契約識別；不允許依 UI 當下選項回填既有委託。

## 驗收

測試小台／大台切換、跨年月份、到期日、主檔更新、無效契約、持倉中切換與活動委託中切換。畫面需同時顯示中文商品名、券商商品代碼及契約月份，且行情、持倉、委託三者不一致時不得啟動。
