# Feature 09 — Connectivity, Reconnect, and Safe Pause

> **API 文件唯一來源：實作前必須直接讀取[元大 SPARK API 官方入口](https://www.yuanta.com.tw/file-repository/content/API/page/index.html)及其下方連結的 API 說明文件、範例、元件下載與換版資訊。不得使用專案內既有資料夾、舊 SDK 文件、舊範例或既有程式碼反推 API 規格；若與本 prompt 其他描述衝突，以官方線上文件當下內容為準。**
> **不得臆測：API 名稱、參數、回傳值、事件、錯誤碼、登入方式、環境、平台、位元數與能力都必須有上述官方文件依據；文件未明載者須標成待確認並隔離於 adapter，不得自行補造。**

> 強制使用 Python 開發；連線健康、重連及安全暫停協調器須使用可測試的 Python 實作。

## 任務

建立涵蓋登入、行情、交易、回報及查詢通道的連線健康模型。任一必要通道異常時立即停止產生新交易意圖，且在狀態釐清前不得自動恢復交易。

## 必須實作

- 分別追蹤各通道的 connected/readiness、最後訊息時間、heartbeat、延遲及錯誤，不以單一布林值代表所有連線。
- 行情 stale、回報中斷、交易通道失效、查詢失敗或時鐘大幅偏移時進入 `PausedSafe`；UI 清楚顯示原因與發生時間。
- 重連採有上限的 exponential backoff 加 jitter；避免登入風暴，並允許使用者停止。
- 重連成功後按順序重新登入／訂閱、查詢活動委託、成交與持倉、回補行情／K 棒並進行 reconciliation。
- 重連前曾提交但未確定的委託一律保持 `Unknown`，只做查詢，不因 client timeout 自動重送。
- 所有健康檢查成功也只能進入 `PausedSafe/Reconciled`；必須由使用者按下繼續／啟動，不得自行恢復自動交易或追補斷線期間訊號。
- 暫停不等於取消既有委託；若產品需要取消，必須是獨立、可追蹤且依券商確認的人工動作。

## 驗收

以故障注入測試行情單獨斷線、交易單獨斷線、全部斷線、heartbeat 假陽性、重連失敗、重連期間晚到成交及狀態查詢矛盾。驗證安全暫停延遲、退避行為、沒有重複下單，且只有完成 reconciliation 與人工確認後才能再次執行。
